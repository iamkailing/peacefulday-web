# Peaceful Day: เว็บไซต์และระบบจอง

เว็บไซต์ของร้าน (ไทย/อังกฤษ) ระบบจองพร้อมชำระเงินออนไลน์ และหลังบ้าน `/admin` สำหรับทีมงานกับเจ้าของร้าน ใช้ฐานข้อมูลเดียวกัน

- **ลูกค้า:** ดูรอบว่างจริง → เลือกวัน เวลา และจำนวนคน → จ่ายด้วย PromptPay หรือบัตร → ได้รหัสการจองและ QR สำหรับเช็คอิน เลื่อนหรือยกเลิกเองได้ตามกติกาที่ร้านตั้ง
- **หน้าร้าน:** ตารางรอบรายวัน/สัปดาห์ เช็คอินด้วย QR บันทึกลูกค้า walk-in/โทร/LINE และรับเงินหน้าร้าน
- **เจ้าของร้าน:** ภาพรวมวันนี้ รายงานรายได้ การใช้ที่นั่ง ลูกค้าใหม่/เก่า และความคุ้มค่าโฆษณา

> หน้า [สิ่งที่ทำงานจริงแล้ว และสิ่งที่ยังจำลอง](#สิ่งที่ทำงานจริงแล้ว-และสิ่งที่ยังจำลอง) สรุปว่าส่วนไหนพร้อมใช้ ส่วนไหนต้องตั้งค่าเพิ่ม

## ขึ้นเว็บจริงแบบทีละขั้น (Render)

ใช้เวลาประมาณ 1–2 ชั่วโมง ทำตามลำดับได้เลย ไม่ต้องเขียนโค้ด

### ขั้นที่ 0: สิ่งที่ต้องมี

| บัญชี | ใช้ทำอะไร | ค่าใช้จ่าย |
|---|---|---|
| [GitHub](https://github.com) | เก็บไฟล์ของเว็บ | ฟรี |
| [Render](https://render.com) | ที่ฝากเว็บและฐานข้อมูล (เซิร์ฟเวอร์สิงคโปร์) | เว็บ ~$7/เดือน + ฐานข้อมูล ~$6/เดือน (ประมาณ 450 บาท/เดือน) |
| [Stripe](https://dashboard.stripe.com/register) (บัญชีธุรกิจในไทย) | รับเงิน PromptPay และบัตร | ไม่มีรายเดือน คิดค่าธรรมเนียมต่อรายการ (ดูอัตราล่าสุดใน Stripe) |
| อีเมลสำหรับส่งใบยืนยัน เช่น Gmail / Google Workspace | ส่งอีเมลยืนยัน แจ้งเตือน และลิงก์เข้าสู่ระบบของลูกค้า | ฟรี |

> PromptPay ผ่าน Stripe ใช้ได้กับบัญชี Stripe ที่จดทะเบียนในประเทศไทยเท่านั้น

### ขั้นที่ 1: อัปโหลดไฟล์ขึ้น GitHub

1. เข้า github.com → มุมขวาบนกด **+** → **New repository**
2. ตั้งชื่อ เช่น `peacefulday-web` → เลือก **Private** → กด **Create repository**
3. ในหน้าที่ขึ้นมา กดลิงก์ **uploading an existing file**
4. แตกไฟล์ zip ที่ได้รับ เปิดโฟลเดอร์ `peacefulday` แล้วลาก **ทุกไฟล์และโฟลเดอร์ข้างใน** (เช่น `cmd`, `internal`, `go.mod`, `render.yaml`, `README.md`) มาวางในหน้าเว็บ
   - ต้องเห็นไฟล์ `render.yaml` อยู่ชั้นบนสุดของ repository ไม่ใช่อยู่ในโฟลเดอร์ย่อย
   - ไฟล์ที่ชื่อขึ้นต้นด้วยจุด (`.gitignore`, `.env.example`) อาจถูกซ่อนในเครื่อง ไม่อัปโหลดก็ได้
5. กด **Commit changes**

> ถ้าลากทั้งโฟลเดอร์ไม่ได้ ใช้โปรแกรม [GitHub Desktop](https://desktop.github.com) แทน: File → Add local repository → เลือกโฟลเดอร์ → Publish repository

### ขั้นที่ 2: สร้างเว็บบน Render

1. เข้า render.com → สมัครด้วยบัญชี GitHub
2. กด **New +** → **Blueprint** → เลือก repository `peacefulday-web` (ถ้าไม่เห็น ให้กด *Configure GitHub* แล้วอนุญาต repository นี้)
3. Render จะอ่าน `render.yaml` และแสดงว่าจะสร้าง **peacefulday** (เว็บ) และ **peacefulday-db** (ฐานข้อมูล) ที่สิงคโปร์
4. Render จะถามค่าตั้งค่า กรอกแบบนี้:

   | ช่อง | ใส่อะไร |
   |---|---|
   | `BOOTSTRAP_OWNER_EMAIL` | อีเมลที่เจ้าของร้านจะใช้เข้าหลังบ้าน |
   | `BOOTSTRAP_OWNER_PASSWORD` | รหัสผ่านแรก อย่างน้อย 10 ตัวอักษร (เปลี่ยนได้ทีหลัง) |
   | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | เว้นว่างไว้ก่อน (ถ้าบังคับกรอก ใส่ `-`) |
   | `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `ADMIN_ALERT_EMAIL` | เว้นว่างไว้ก่อนได้ (ทำในขั้นที่ 5) |

5. กด **Apply** แล้วรอประมาณ 5–10 นาที จนสถานะเว็บเป็น **Live**
6. กดชื่อเว็บ **peacefulday** จะเห็นที่อยู่เว็บ เช่น `https://peacefulday-xxxx.onrender.com` เปิดดูได้เลย

ตอนนี้เว็บอยู่ใน **โหมดทดสอบ** (`APP_ENV=staging`, `PAYMENT_PROVIDER=simulated`) ทุกหน้ามีแถบแจ้งว่า "โหมดทดสอบ" การจ่ายเงินเป็นหน้าจำลอง ยังไม่มีเงินจริง

### ขั้นที่ 3: เข้าหลังบ้านครั้งแรก

1. เปิด `https://ที่อยู่เว็บ/admin` → ใช้อีเมลและรหัสผ่านจากขั้นที่ 2
2. ไปที่ **บัญชีของฉัน** → เปลี่ยนรหัสผ่าน
3. ไปที่ **ทีมงานและสิทธิ์** → เพิ่มพนักงาน (หน้าร้าน / ผู้จัดการ / การตลาด / การเงิน)
4. ตรวจและแก้ข้อมูลร้าน (ระบบใส่ค่าเริ่มต้นจากชีตและสคริปต์ของร้านไว้แล้ว):
   - **ตารางเปิดรอบ:** รอบทุกชั่วโมง 09:00–20:00 รอบละ 5 คน หยุดวันพฤหัส
   - **สินค้าและราคา:** รอบเดี่ยว 590 บาท/คน โปร Happy Duo / Group / Family เป็น "ร่าง" (ยังไม่ขาย เพราะโปรเดิมหมดเขต 5 ก.ค.) กด "แก้ไข" → ติ๊ก "เปิดขาย" เมื่ออนุมัติแล้ว
   - **ตั้งค่า:** เบอร์โทร ที่อยู่ กติกายกเลิก/เลื่อน (ค่าเริ่มต้น: ทำเองได้ก่อน 24 ชม. เลื่อนได้ 1 ครั้ง ยกเลิกแล้วคืนเป็นเครดิต) และข้อความ "เรื่องราวของเรา"
   - **เนื้อหาเว็บและ SEO:** อัปโหลดรูปจริงของร้าน (ภาพตัวอย่างบนเว็บจะถูกแทนทันที) และเพิ่มรีวิวจริงพร้อมลิงก์ต้นฉบับ

### ขั้นที่ 4: ทดลองทั้งระบบในโหมดทดสอบ

1. เปิดหน้าเว็บ → **จองรอบ** → เลือกวัน เวลา จำนวนคน → กรอกข้อมูล → **ไปชำระเงิน**
2. หน้าชำระเงินจำลองจะมีปุ่ม "จ่ายด้วย PromptPay สำเร็จ" / "จ่ายไม่สำเร็จ" ให้ลองทั้งสองแบบ
3. หลังจ่ายสำเร็จจะเห็นหน้า "จองเรียบร้อยแล้ว" พร้อม QR
4. ในหลังบ้าน → **เช็คอิน** → พิมพ์รหัสการจอง หรือสแกน QR (กล้องใช้ได้บน Chrome/Android ส่วนเครื่องสแกนแบบ USB/บลูทูธใช้ได้ทุกเครื่อง)
5. ลองเลื่อนรอบหรือยกเลิกจากหน้าการจองของลูกค้า แล้วดูผลในหลังบ้าน

> อยากเห็นรายงานที่มีตัวเลขก่อนมีลูกค้าจริง: ใน Render เปิดเว็บ → **Shell** → พิมพ์ `./bin/server -seed-demo` ระบบจะใส่ข้อมูลตัวอย่างที่ติดป้าย DEMO ทุกแถว ลบออกด้วย `./bin/server -purge-demo` (คำสั่งนี้ใช้ไม่ได้เมื่อเป็น production)

### ขั้นที่ 5: ตั้งค่าอีเมล

ใช้ส่งอีเมลยืนยันการจอง เตือนก่อนถึงรอบ ยกเลิก/เลื่อน และลิงก์เข้าสู่ระบบของลูกค้า ตัวอย่างนี้ใช้ Gmail / Google Workspace:

1. เปิดการยืนยันตัวตนแบบ 2 ขั้นตอนของบัญชี Google
2. ไปที่ myaccount.google.com → ค้นหา **App passwords** → สร้างรหัสสำหรับแอป ชื่อ "Peaceful Day" → จะได้รหัส 16 ตัว
3. ใน Render → เว็บ **peacefulday** → **Environment** → แก้ค่า แล้วกด **Save changes** (เว็บจะรีสตาร์ตเอง):

   | Key | Value |
   |---|---|
   | `SMTP_HOST` | `smtp.gmail.com` |
   | `SMTP_PORT` | `587` |
   | `SMTP_USER` | อีเมล Gmail ของร้าน |
   | `SMTP_PASS` | รหัส 16 ตัวจากข้อ 2 |
   | `SMTP_FROM` | `Peaceful Day <อีเมลของร้าน>` |
   | `ADMIN_ALERT_EMAIL` | อีเมลที่อยากรับแจ้งเตือนการจองใหม่และปัญหาของระบบ |

4. ลองจองอีกครั้ง แล้วดูผลในหลังบ้าน → **การแจ้งเตือน** (สถานะ "ส่งแล้ว")

> Gmail ส่วนตัวส่งได้ประมาณ 500 ฉบับ/วัน ถ้าร้านใหญ่ขึ้น เปลี่ยนไปใช้บริการส่งอีเมลโดยเฉพาะ (เช่น Brevo, Postmark, Resend) ได้ทันที เพียงเปลี่ยนค่า SMTP ชุดเดียวกันนี้

### ขั้นที่ 6: เชื่อม Stripe (เริ่มจากโหมดทดสอบ)

1. สมัคร Stripe → เลือกประเทศ **Thailand** → กรอกข้อมูลธุรกิจ
2. Stripe Dashboard → **Settings → Payment methods** → เปิด **PromptPay** และ **Cards**
3. เปิดสวิตช์ **Test mode** (มุมขวาบน) → **Developers → API keys** → คัดลอก **Secret key** (`sk_test_...`)
4. **Developers → Webhooks** (บางบัญชีอยู่ใต้ Workbench → Event destinations) → **Add endpoint**
   - Endpoint URL: `https://ที่อยู่เว็บ/webhooks/stripe`
   - Events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `charge.succeeded`, `charge.refunded`
   - กดสร้าง แล้วคัดลอก **Signing secret** (`whsec_...`)
5. ใน Render → **Environment** ใส่ค่าแล้วกด **Save changes**:

   | Key | Value |
   |---|---|
   | `PAYMENT_PROVIDER` | `stripe` |
   | `STRIPE_SECRET_KEY` | `sk_test_...` |
   | `STRIPE_WEBHOOK_SECRET` | `whsec_...` |
   | `APP_ENV` | `production` |

6. ลองจองแล้วจ่ายด้วยบัตรทดสอบ `4242 4242 4242 4242` (วันหมดอายุใดก็ได้ในอนาคต CVC ใดก็ได้) หรือเลือก PromptPay (หน้าทดสอบของ Stripe มีปุ่มให้กดอนุมัติ)
7. ตรวจว่าการจองเปลี่ยนเป็น "ยืนยันแล้ว" และใน Stripe → Webhooks เห็นสถานะ 200

> แถบ "โหมดทดสอบ" จะยังแสดงตราบใดที่ใช้คีย์ `sk_test_` เพื่อไม่ให้ลูกค้าเข้าใจผิด

### ขั้นที่ 7: ใช้โดเมนของร้าน

1. Render → เว็บ → **Settings → Custom Domains** → **Add** เช่น `www.peacefulday.co.th`
2. ทำตามที่ Render บอกในระบบ DNS ของผู้ให้บริการโดเมน (เพิ่ม CNAME) รอจนขึ้นว่า Verified (HTTPS ทำให้อัตโนมัติ)
3. แก้ `BASE_URL` ใน Environment เป็น `https://www.peacefulday.co.th` (ลิงก์ในอีเมลและการจ่ายเงินใช้ค่านี้)
4. แก้ Endpoint URL ของ webhook ใน Stripe ให้เป็นโดเมนใหม่

### ขั้นที่ 8: เปิดรับเงินจริง (ทำครบทุกข้อก่อนเปิด)

- [ ] บัญชี Stripe ผ่านการยืนยันตัวตนธุรกิจแล้ว (Activate account)
- [ ] ปิด Test mode → **Developers → API keys** คัดลอก `sk_live_...`
- [ ] สร้าง webhook endpoint ใหม่ **ในโหมด live** (Event ชุดเดียวกับขั้นที่ 6) แล้วคัดลอก `whsec_...` ของ live
- [ ] ใส่ `STRIPE_SECRET_KEY` และ `STRIPE_WEBHOOK_SECRET` ชุด live ใน Render แล้ว Save
- [ ] `APP_ENV=production` และ `BASE_URL` เป็นโดเมนจริง
- [ ] ส่งอีเมลได้แล้ว (ขั้นที่ 5)
- [ ] ตรวจราคา ตารางรอบ จำนวนคนต่อรอบ กติกายกเลิก/คืนเงิน หน้าเงื่อนไข และนโยบายความเป็นส่วนตัวให้ตรงกับที่ร้านใช้จริง (แนะนำให้ที่ปรึกษากฎหมายอ่านหน้า Terms และ Privacy)
- [ ] แทนภาพตัวอย่างด้วยรูปจริงของร้าน
- [ ] ถ้ามีข้อมูลตัวอย่าง ลบด้วย `./bin/server -purge-demo` ก่อนเปลี่ยนเป็น production
- [ ] จองจริงด้วยเงินจริง 1 รายการ แล้วลองคืนเงินจากหลังบ้าน (การจอง → การชำระเงิน → คืนเงิน) ให้เห็นว่าครบวงจร

## สิ่งที่ทำงานจริงแล้ว และสิ่งที่ยังจำลอง

**ทำงานจริงแล้ว**
- เว็บไซต์ไทย/อังกฤษ หน้าแรก ประสบการณ์ ราคา เรื่องราว แกลเลอรี FAQ ติดต่อ/แผนที่ นโยบาย 3 หน้า, sitemap.xml, robots.txt, ข้อมูลธุรกิจแบบ schema.org
- ระบบจอง:
  - ความจุต่อรอบ และกันที่ชั่วคราวระหว่างจ่ายเงิน (ค่าเริ่มต้น 30 นาที หมดเวลาแล้วปล่อยที่คืนอัตโนมัติ)
  - กันจองเกินแม้มีหลายคนกดจ่ายพร้อมกัน (ล็อกระดับฐานข้อมูล)
  - กันจองซ้ำ และกันการกดซ้ำ (idempotency)
  - ปิดวัน/ปิดปรับปรุง และปรับความจุเฉพาะวันหรือเฉพาะรอบ
  - เวลา Asia/Bangkok ทั้งระบบ
- การชำระเงินผ่าน Stripe Checkout (PromptPay + บัตร):
  - ยืนยันการจองจาก webhook ที่ตรวจลายเซ็นแล้วเท่านั้น ประมวลผลซ้ำไม่ได้ และตรวจยอดเงินทุกครั้ง
  - จ่ายช้าหลังหมดเวลากันที่: ถ้ายังมีที่ระบบยืนยันให้ ถ้าเต็มแล้วคืนเงินอัตโนมัติและขึ้นเตือนทีมงาน
  - คืนเงินเต็มจำนวนหรือบางส่วนจากหลังบ้าน การคืนเงินที่ทำใน Stripe Dashboard ก็ถูกบันทึกเข้าระบบ
  - ระบบไม่เห็นและไม่เก็บเลขบัตร
- ลูกค้า:
  - หน้าการจองพร้อม QR เพิ่มลงปฏิทิน (.ics) เลื่อนรอบ และยกเลิกตามกติกา
  - หน้า "การจองของฉัน" ค้นด้วยรหัสการจองกับเบอร์โทร หรือเข้าด้วยลิงก์ทางอีเมลโดยไม่ต้องมีรหัสผ่าน แสดงสิทธิ์แพ็กเกจคงเหลือ
- แพ็กเกจและบัตรของขวัญ: ขายออนไลน์ ใช้รหัสบัตรตอนจอง ตัดสิทธิ์อัตโนมัติ และคืนสิทธิ์เมื่อยกเลิก
- หลังบ้าน:
  - งานประจำวัน: ภาพรวมวันนี้พร้อมเทียบสัปดาห์ก่อน ตารางรอบ จองให้ walk-in/โทร/LINE (เก็บเงินที่ร้านหรือส่งลิงก์จ่าย) เช็คอินด้วย QR บันทึกไม่มา ย้ายรอบ แก้จำนวนคน ยกเลิกและคืนเงิน
  - ลูกค้า: ประวัติ ยอดใช้จ่าย สิทธิ์คงเหลือ แท็ก โน้ต กลุ่มลูกค้า และดาวน์โหลด CSV
  - การขาย: ตารางรอบ สินค้า/ราคา โค้ดส่วนลด (รวมโค้ดแนะนำเพื่อน) แพ็กเกจ รูปภาพ รีวิว (ต้องมีลิงก์ต้นฉบับ) SEO และหน้าแคมเปญ `/lp/...`
  - ระบบ: ทีมงาน 5 ตำแหน่ง บันทึกการเปลี่ยนแปลง (audit log) และบันทึกการแจ้งเตือนที่สั่งส่งซ้ำได้
- รายงานธุรกิจ:
  - เลือกช่วงวันนี้ / เมื่อวาน / 7 วัน / 30 วัน / 90 วัน / กำหนดเอง และเทียบกับช่วงก่อนหน้า
  - ตัวเลข: รายได้สุทธิ ยอดคืนเงิน ยอดเฉลี่ยต่อบิล % การใช้ที่นั่งตามวัน-เวลา ลูกค้าใหม่/เก่า cohort และ funnel
  - การตลาด: ที่มาลูกค้า (UTM) ROAS ต้นทุนต่อการจอง และจำนวนการทิ้งตะกร้า
  - ดาวน์โหลด CSV ได้ ตัวเลขประมาณการติดป้าย "ประมาณการ" และข้อมูลที่ระบบไม่มีแสดงไว้ชัดเจน
- อีเมล (เมื่อตั้งค่า SMTP): ยืนยันการจอง เตือนก่อนถึงรอบ เลื่อน ยกเลิก (พร้อมรหัสเครดิต) แจ้งเตือนทีมงาน และลิงก์เข้าสู่ระบบ ระบบลองส่งซ้ำให้อัตโนมัติ
- การวัดผล (เมื่อใส่รหัสในหลังบ้าน):
  - เครื่องมือที่รองรับ: GA4, Google Tag Manager, Google Ads conversion, Meta Pixel
  - Meta Conversions API ส่งได้เมื่อตั้ง `META_CAPI_ACCESS_TOKEN`
  - โหลดเครื่องมือเหล่านี้หลังลูกค้ากดยอมรับคุกกี้เท่านั้น และใช้รหัสการจองเป็นรหัสเหตุการณ์เพื่อไม่ให้นับซ้ำ

**ยังจำลอง หรือยังไม่มี**
- หน้าจ่ายเงินจำลอง (`PAYMENT_PROVIDER=simulated`) ใช้ได้เฉพาะ development/staging และระบบไม่ยอมเปิดในโหมด production
- **LINE OA:** ยังไม่ได้เชื่อม (เตรียมช่องทางไว้แล้ว ต้องใช้ LINE Login เพื่อรู้ LINE ID ของลูกค้า)
- **อีเมลการตลาดอัตโนมัติ / ตามลูกค้าที่ทิ้งตะกร้า:** ตอนนี้มีรายงานและรายชื่อลูกค้าที่ยินยอม (CSV) แต่ยังไม่ส่งข้อความอัตโนมัติ
- **สถิติจากแพลตฟอร์มโฆษณา** (การมองเห็น คลิก CPC): ยังไม่ดึงจาก Meta/Google ค่าโฆษณาต้องบันทึกเองในหลังบ้านเพื่อคำนวณ ROAS
- **ใบกำกับภาษี:** ลูกค้าได้ใบเสร็จของ Stripe แต่ระบบยังไม่ออกใบกำกับภาษีตามกฎหมายไทย
- **สมาชิกรายเดือนแบบตัดบัตรอัตโนมัติ:** ตอนนี้ทำเป็นแพ็กเกจเครดิตได้ แต่ยังไม่ตัดเงินทุกเดือน
- **ย้ายข้อมูลจากชีตเดิม:** การจองและแพ็กเกจที่ลูกค้าซื้อไว้ในชีตยังไม่ได้ย้ายเข้ามา ย้ายแพ็กเกจทีละรายการได้ในหลังบ้าน → แพ็กเกจและบัตร → ออกบัตรด้วยตนเอง

**เรื่องที่ควรรู้เกี่ยวกับการคืนเงิน PromptPay:** การคืนเงินผ่าน Stripe ต้องให้ลูกค้ากรอกเลขบัญชีที่ใช้จ่าย Stripe จะส่งอีเมลขอข้อมูลจากลูกค้าเอง ถ้าลูกค้าไม่ตอบ การคืนเงินจะไม่สำเร็จ ส่วนบัตรคืนอัตโนมัติ ค่าเริ่มต้นของร้านจึงตั้งให้ "ยกเลิกแล้วคืนเป็นเครดิต" (เปลี่ยนได้ในหน้าตั้งค่า)

## การสำรองข้อมูลและกู้คืน

- **อัตโนมัติ:** ฐานข้อมูลแบบเสียเงินของ Render มีการสำรองข้อมูลทุกวัน และกู้คืนย้อนหลังแบบระบุเวลาได้ (ดูได้ที่ฐานข้อมูล → **Recovery**) ระยะย้อนหลังขึ้นกับแพ็กเกจของ Render
- **สำรองเอง (แนะนำทุกสัปดาห์หรือทุกเดือน):** Render → ฐานข้อมูล → **Connect** → คัดลอก *External Database URL* แล้วรันบนเครื่องที่มี PostgreSQL:
  ```
  pg_dump "EXTERNAL_DATABASE_URL" -Fc -f peacefulday-YYYYMMDD.dump
  ```
  กู้คืนลงฐานข้อมูลใหม่ด้วย `pg_restore --clean --no-owner -d "DATABASE_URL" peacefulday-YYYYMMDD.dump`
- **ข้อมูลที่ดาวน์โหลดได้จากหลังบ้าน:** การจอง ลูกค้า การชำระเงิน และรายงานรายวัน (CSV) การดาวน์โหลดทุกครั้งถูกบันทึกใน audit log
- อย่าใช้ฐานข้อมูลแบบฟรีกับร้านจริง เพราะ Render ลบทิ้งหลัง 30 วัน และไม่มีการสำรองข้อมูล

## การดูแลระบบ

- **สถานะ:** `https://ที่อยู่เว็บ/healthz` ตอบ `{"ok":true}` เมื่อเว็บและฐานข้อมูลปกติ Render ใช้ลิงก์นี้ตรวจสุขภาพและรีสตาร์ตให้เองเมื่อมีปัญหา แนะนำตั้ง [UptimeRobot](https://uptimerobot.com) (ฟรี) เช็กลิงก์นี้ทุก 5 นาทีแล้วแจ้งเตือนเข้าอีเมล
- **Logs:** Render → เว็บ → **Logs** (ทุก request และข้อผิดพลาดเป็น JSON)
- **แจ้งเตือนอัตโนมัติ:** ถ้าตั้ง `ADMIN_ALERT_EMAIL` ระบบส่งอีเมลเมื่อมีการจองใหม่ เกิดข้อผิดพลาด หรือคืนเงินอัตโนมัติไม่สำเร็จ
- **หน้า "ภาพรวมวันนี้"** แสดง webhook ที่ค้างและอีเมลที่ส่งไม่สำเร็จ
- **ลืมรหัสผ่านเจ้าของร้าน:** Render → เว็บ → **Shell** → `NEW_PASSWORD='รหัสใหม่อย่างน้อย10ตัว' ./bin/server -reset-password owner@email`
- **ตรวจกระทบยอด:** หลังบ้าน → **การชำระเงิน** → ดาวน์โหลด CSV เทียบกับ Stripe → Payments → Export

## ทำไมเลือก Stripe

- **PromptPay + บัตรในหน้าเดียว:** Stripe Checkout เป็นหน้าชำระเงินของ Stripe เอง จึงไม่มีเลขบัตรผ่านระบบของร้าน ภาระด้าน PCI DSS น้อยที่สุด
- **ยืนยันจาก webhook ที่มีลายเซ็น:** ระบบจับคู่การจ่ายเงินกับการจองได้แม่นยำ และ Stripe ส่งซ้ำให้อัตโนมัติถ้าเว็บล่มชั่วคราว
- **คืนเงินผ่าน API ได้ทั้งบัตรและ PromptPay:** ทั้งคืนเต็มจำนวนและคืนบางส่วน และมีโหมดทดสอบที่ใช้ได้ครบ
- **ทางเลือกอื่น:** ผู้ให้บริการในไทย (เช่น Omise/Opn, 2C2P) ใช้ได้เช่นกัน ระบบแยกส่วนผู้ให้บริการชำระเงินไว้ (`PaymentProvider` ใน `internal/app/payments.go`) จึงเพิ่มผู้ให้บริการอื่นได้โดยไม่ต้องแก้ส่วนอื่น

## สำหรับนักพัฒนา

**เทคโนโลยี:** Go 1.24 (ไลบรารีมาตรฐาน + `lib/pq` + `go-qrcode`), PostgreSQL 16, HTML template ฝั่งเซิร์ฟเวอร์, CSS/JS ไม่มี framework ฟอนต์ Anuphan + Maitree (SIL OFL) โหลดจากเซิร์ฟเวอร์ของเว็บเอง ทั้งหมดรวมเป็นไฟล์โปรแกรมเดียว

```
cmd/server/main.go            จุดเริ่มโปรแกรม + คำสั่ง -migrate / -seed-demo / -purge-demo / -reset-password
internal/app/
  core.go                     config, ฐานข้อมูล, migration, เวลา, เงิน, รหัส, crypto, settings, audit
  booking.go                  booking engine (ความจุ, กันที่, ราคา, ยกเลิก, เลื่อน, เช็คอิน)
  payments.go                 Stripe + ผู้ให้บริการจำลอง, webhook, คืนเงิน, แพ็กเกจ
  notify.go                   outbox อีเมล / Meta CAPI พร้อมส่งซ้ำ
  handlers_public.go          หน้าเว็บลูกค้า + API การจอง
  admin_core.go, admin_manage.go   หลังบ้าน
  analytics.go, charts.go     รายงานธุรกิจ
  seed.go, site.go, i18n.go   ข้อมูลเริ่มต้น, ข้อมูลร้าน, ภาษาไทย/อังกฤษ
  migrations/*.sql            โครงสร้างฐานข้อมูล
  templates/, static/         หน้าเว็บ, CSS, JS, ฟอนต์, รูป
```

**รันบนเครื่อง**
```bash
createdb peacefulday                      # PostgreSQL 14+
go run ./cmd/server -seed-demo            # สร้างตาราง + ข้อมูลตัวอย่าง (DEMO)
ASSETS_DIR=./internal/app go run ./cmd/server
# เว็บ: http://localhost:8080   หลังบ้าน: /admin  (owner@demo.local / peacefulday-demo — เฉพาะ development)
```
ค่าตั้งค่าทั้งหมดอยู่ใน `.env.example`

**ทดสอบ** (ใช้ฐานข้อมูลจริงเพราะความปลอดภัยของการจองมาจาก lock และ constraint ของฐานข้อมูล)
```bash
createdb peacefulday_test
go test ./internal/app -race -v           # หรือกำหนด TEST_DATABASE_URL
```
ชุดทดสอบครอบคลุม:
- กดจองพร้อมกัน 25 คนในรอบ 5 ที่ (ต้องได้ 5 พอดี) และจองเป็นกลุ่ม
- กดซ้ำ (idempotency) จองซ้ำด้วยเบอร์หรืออีเมลเดิม และลองจองใหม่หลังทิ้งหน้าจ่ายเงิน
- ข้อมูลไม่ถูกต้อง รอบที่ปิดหรือผ่านไปแล้ว และกันที่หมดเวลา
- ราคากับโค้ดส่วนลดหรือบัตร และการคืนสิทธิ์
- กติกายกเลิกเอง คืนเป็นเครดิต และการเลื่อนรอบ
- ไม่ยืนยันการจองถ้าไม่มี webhook หรือยอดเงินไม่ตรง
- ลายเซ็น Stripe: ปลอม เก่า หรือถูกแก้
- webhook ซ้ำ และคืนเงินจาก Dashboard
- คืนเงินซ้ำ และการจ่ายช้าเมื่อที่เต็ม
- CSRF และสิทธิ์เข้าหน้า การแสดงผลทุกหน้า สิทธิ์ตามตำแหน่ง และการส่งอีเมล

**ความปลอดภัยที่ทำไว้**
- เข้าถึงข้อมูล:
  - รหัสผ่านทีมงานเก็บแบบ PBKDF2-SHA256 ใส่ผิด 5 ครั้งล็อก 15 นาที และ session หมดอายุใน 12 ชั่วโมง
  - ลิงก์จัดการการจองของลูกค้าเป็น token ที่เก็บแบบ hash หรือลิงก์ที่ลงลายเซ็น และ QR เช็คอินลงลายเซ็นกันปลอม
  - ไม่เก็บข้อมูลบัตร และความลับทั้งหมดอยู่ใน environment variables
- ป้องกันการโจมตี:
  - CSRF ทุกฟอร์มและ API, rate limit การจอง/ล็อกอิน/ค้นหา
  - CSP ไม่อนุญาต inline script, HSTS
- ตรวจสอบย้อนหลังได้: audit log สำหรับการเปลี่ยนแปลงและการดาวน์โหลดข้อมูลทุกครั้ง
